## 🏛️ Web Application & Web Service Concepts

### Web Applications
Web applications provide a dynamic interface between end-users and web servers. They generate pages on the server side or distribute client-side scripts to execute within a browser. Despite enforcing strict policies, they are highly targeted and susceptible to attacks like SQL Injection, Session Hijacking, and Cross-Site Scripting (XSS).

### Multi-Tier Architecture
Traditional web environments operate across structured operational layers:
1. **Clients:** Browsers, smartphones, and web appliances.
2. **Presentation Layer:** The front-facing web server handling firewalls, routing, and incoming request parsing (HTML, CSS).
3. **Business/Application Layer:** Implements core business logic using backend languages (Java, PHP, Python, etc.).
4. **Database Layer:** Manages persistent storage, cloud structures, and Data Base Management Systems (DBMS).

### Web Services
Software systems deployed online to allow cross-platform applications to interact using standardized messaging protocols:
* **SOAP (Simple Object Access Protocol):** Relies heavily on XML formats to transfer structured data between a requestor and a provider.
* **RESTful APIs:** Leverage native HTTP methods (GET, POST, PUT, DELETE) to optimize data delivery, speed, and efficiency.
* **Core Components:** Service Requester, Service Registry (utilizing UDDI/WSDL for discovery), and Service Provider.

## ⚠️ Web Application Threats (OWASP Top 10)

The core lecture materials review critical application vulnerabilities outlined in the **OWASP Top 10**:

* **A01: Broken Access Control:** Occurs when authorization systems fail to enforce restrictions. Attackers bypass validation checks to act with administrative privileges (creating, reading, updating, or deleting protected data).
* **A02: Cryptographic Failures / Sensitive Data Exposure:** Arises when data at rest or in transit is poorly secured. This includes weak cryptographic storage, data leakage, or systemic flaws in underlying encryption code.
* **A03: Injection Flaws:** Untrusted input is incorrectly interpreted by an interpreter as a command or query.
  * *SQL Injection (SQLi):* Directly manipulating database queries via input parameters.
  * *Command Injection:* Executing arbitrary operating system commands through web forms.
  * *LDAP Injection:* Supplying malicious statements to manipulate directory service access.
  * *Cross-Site Scripting (XSS):* Injecting malicious scripts (like JavaScript) into web pages viewed by other users.
* **A04: Insecure Design:** Architectural flaws resulting from a failure to integrate foundational security controls during the planning phase.
* **A05: Security Misconfiguration:** Hardening failures across the application stack, such as leaving default credentials active, unvalidated input forms, or enabling verbose error messages that expose underlying logic.
* **A06: Vulnerable and Outdated Components:** Using legacy libraries or software frameworks that contain known, unpatched CVEs.

## 🔐 Cryptographic Implementations

Below is a direct comparison between insecure "security through obscurity" practices and industry-standard Java encryption.

### ❌ Vulnerable Implementation (Anti-Pattern)
This code snippet attempts to protect data using simple character substitution (`'a'` with `'z'`, `'b'` with `'y'`). It lacks mathematical security, offers zero actual protection, and is trivial to reverse-engineer.

```java
public String encrypt(String plainText) {
    plainText = plainText.replace("a", "z");
    plainText = plainText.replace("b", "y");
    // Insecure: lacks cryptographic strength and is easily broken.
    return plainText;
}
